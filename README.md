# Finance

Angular and NestJS deployed together as one Cloudflare Worker named `finance-repo`.
Run the deployment commands from the repository root.

## Design reference

Future frontend work follows [DESIGN.md](DESIGN.md) and the user-supplied
[Family Finance HTML template](docs/design/family-finance-design.html).
The original template is saved unchanged as a local, interactive design
reference. Its sample data is illustrative; the live application is unchanged.

## Structure

```text
finance-repo/
├── frontend/                 # Angular application
│   └── dist/frontend/browser/ # Generated static files
├── backend/                  # NestJS application
│   ├── src/
│   │   ├── main.ts           # Normal Node.js server
│   │   └── worker.ts         # Cloudflare Worker entry point
│   ├── dist/worker.js        # Generated by the NestJS build
│   └── migrations/           # Versioned D1 SQL migrations
├── package.json              # Root install/build/deploy commands
├── package-lock.json
└── wrangler.jsonc            # Single deployment configuration
```

`backend/dist/` and `frontend/dist/` are generated and are not committed.
NestJS is compiled before Wrangler bundles it, preserving decorator metadata.
Cloudflare serves Angular's files and forwards `/api/*` to NestJS on the same
origin. Other browser routes fall back to Angular's `index.html`.

## Install and build

Use Node.js 24 LTS (24.15 or newer) and npm. From the repository root:

```sh
npm ci
npm run build
```

The root install automatically runs `npm ci` in `backend/` and `frontend/`, using
all three committed lockfiles. The build generates Worker types, compiles NestJS
into `backend/dist/`, and builds Angular into `frontend/dist/frontend/browser/`.
The types command creates its output directory first, so no generated files or
directories need to exist on a fresh checkout.

To validate packaging without deploying:

```sh
npm run deploy:check
```

## Deploy with Cloudflare Workers Builds (Git integration)

Connect `seregka23/finance-repo` to the **finance-repo** Worker in Cloudflare.
After this PR is merged, use these build settings:

| Setting | Value |
| --- | --- |
| Root directory | Repository root (leave blank or use `/`) |
| Build command | `npm run build` |
| Deploy command | `npx wrangler deploy --env ""` |
| Node.js version | `24` (`NODE_VERSION=24` if a build variable is needed) |

The root `package-lock.json` selects npm and pins Wrangler. Cloudflare's automatic
npm install runs the root `postinstall`, which installs both applications. If you
have disabled automatic dependency installation, use `npm ci && npm run build`
as the build command instead.

The deploy command runs after the build; it does not need to rebuild the apps.
The empty environment selects the existing top-level test deployment explicitly.
An older `npx wrangler deploy` setting still uses that target, with a Wrangler
warning about choosing an environment.
The Worker name in `wrangler.jsonc` matches the existing `finance-repo` Worker.
Use Workers Builds, rather than a Pages-only static deployment, because NestJS
runs as Worker code.

## Deploy from your computer

Authenticate Wrangler for the account in `wrangler.jsonc`:

```sh
npx wrangler login
npm run deploy
```

`npm run deploy` builds both applications and then runs Wrangler. In CI, use a
scoped `CLOUDFLARE_API_TOKEN` secret instead of interactive login. Never commit a
token. The connected Cloudflare app and local Wrangler have separate credentials.

Deployment is an explicit action: installing, building, testing and the dry run
do not deploy or create remote resources.

## D1 database

All targets are explicit in `wrangler.jsonc`. D1 bindings and variables are
declared for every named environment because Wrangler does not inherit them.

| Target | Worker | Database | Probe writes |
| --- | --- | --- | --- |
| Default (existing Git deployment) | `finance-repo` | Existing `family-finance-test` | Disabled |
| `--env local --local` | Local simulator | Dedicated local-only simulator ID | Enabled on loopback hosts only |
| `--env test` | `finance-repo-test` | Existing `family-finance-test` | Disabled |
| `--env production` | Proposed `finance-repo-production` | **Unconfigured placeholder; separate production D1 required** | Disabled |

The default remains an alias for the current test deployment so existing Git
build settings keep working. It does not become a production environment.
Local development never uses remote bindings. No production database has been
created or migrated for this issue; replace the clearly marked production ID
placeholder with a real separate database only after agreeing the production
environment. Never substitute a local simulator or test ID for production.

The existing infrastructure migration is unchanged. Migration `0002` adds the
[household finance schema](docs/database/schema.md) with scoped foreign keys,
integer minor units and unique budget, request and import-source keys. It seeds
no records. See the [migration and recovery guide](docs/database/migrations.md)
before applying it to a real database.
Local data is kept under ignored `.wrangler/` state; changing
to the named local environment does not delete earlier simulator data.

Apply migrations to the local simulator:

```sh
npm run db:migrate:local
```

To inspect or apply a future reviewed migration in the explicit test target:

```sh
npx wrangler d1 migrations list DB --env test --remote
npx wrangler d1 migrations apply DB --env test --remote
```

Only after production has a real separate database and a migration/recovery
plan, its explicit command is
`npx wrangler d1 migrations apply DB --env production --remote`.
No remote migration is performed by build or verification commands.

Deploying code does not automatically apply database migrations. Local D1 data
is kept under the ignored root `.wrangler/` directory, separately from remote D1.

## Local development

Run the combined app in the local Workers runtime:

```sh
npm run db:migrate:local
npm run dev:cloudflare
```

This selects `--env local --local`. Open http://localhost:8787. Restart this
command after source changes to rebuild.
`/api/hello` returns `{ "message": "Hello World!" }`; `/api/health` queries the D1
binding and returns `{ "status": "ok", "database": "ok" }`.

### Repeatable Worker/D1 verification

```sh
npm run verify:schema
npm run verify:local
```

`verify:schema` applies the baseline and finance migrations to a disposable local
D1 database. It checks household isolation, uniqueness under simultaneous writes,
money/rate constraints, failed-batch rollback and safe migration replay. See the
[issue #4 acceptance record](docs/verification/issue-4.md).

`verify:local` builds the apps and runs actual Wrangler/Workerd instances against a new,
temporary local D1 store. It applies the versioned migration, creates/reads a
quoted Unicode value through the NestJS API, restarts the Worker, replays the
migration and checks that data/history survive, then deletes the synthetic probe
and disposes of its own state. It does not touch an existing local database or
any remote database. Failures include the relevant local logs.

The proof API is registered only when `INFRASTRUCTURE_PROBE_ENABLED=true`, which
is set only in the local environment. It also rejects non-loopback hosts. With
local Wrangler running, POST `/api/infrastructure/probe` with
`{ "value": "local check" }` returns `{ "id": "<generated UUID>", "value": "local check" }`.
GET and DELETE `/api/infrastructure/probe/<id>` read and clean up that record.
The body accepts only one string field of 1–256 characters. These routes are
absent from default/test/production deployments; this is not a financial API.

See [issue #3 verification and decisions](docs/verification/issue-3.md) for the
acceptance record and remaining production decisions.

For separate Node/Angular development, use two terminals after the root install:

```sh
npm --prefix backend run start:dev
npm --prefix frontend start
```

NestJS listens on port 3000 and Angular on port 4200. Angular's development proxy
forwards `/api/**` to port 3000. The D1 health route belongs to the Worker runtime.

## Checks

```sh
npm --prefix backend test
npm --prefix backend run test:e2e
npm --prefix backend run lint
npm --prefix frontend test -- --watch=false
npm run deploy:check
```

The current app includes the greeting integration and infrastructure health
check. Authentication and financial workflows remain future work.

Wrangler aliases the starter's missing optional NestJS packages to a module that
rejects their import, preserving Nest's optional-package handling. Before adding
class-validator/class-transformer, microservices or WebSockets, install the real
package and remove its corresponding alias from `wrangler.jsonc`.
