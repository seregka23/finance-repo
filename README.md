# Finance

Angular and NestJS deployed together as one Cloudflare Worker named `finance-repo`.
Run the deployment commands from the repository root.

## Structure

```text
finance-repo/
├── frontend/                 # Angular application
│   └── dist/frontend/browser/ # Generated static files
├── backend/                  # NestJS application
│   ├── src/
│   │   ├── main.ts           # Normal Node.js server
│   │   └── worker.ts         # Cloudflare Worker entry point
│   ├── dist/worker.js        # Generated by the NestJS build
│   └── migrations/           # Versioned D1 SQL migrations
├── package.json              # Root install/build/deploy commands
├── package-lock.json
└── wrangler.jsonc            # Single deployment configuration
```

`backend/dist/` and `frontend/dist/` are generated and are not committed.
NestJS is compiled before Wrangler bundles it, preserving decorator metadata.
Cloudflare serves Angular's files and forwards `/api/*` to NestJS on the same
origin. Other browser routes fall back to Angular's `index.html`.

## Install and build

Use Node.js 24 LTS (24.15 or newer) and npm. From the repository root:

```sh
npm ci
npm run build
```

The root install automatically runs `npm ci` in `backend/` and `frontend/`, using
all three committed lockfiles. The build generates Worker types, compiles NestJS
into `backend/dist/`, and builds Angular into `frontend/dist/frontend/browser/`.
The types command creates its output directory first, so no generated files or
directories need to exist on a fresh checkout.

To validate packaging without deploying:

```sh
npm run deploy:check
```

## Deploy with Cloudflare Workers Builds (Git integration)

Connect `seregka23/finance-repo` to the **finance-repo** Worker in Cloudflare.
After this PR is merged, use these build settings:

| Setting | Value |
| --- | --- |
| Root directory | Repository root (leave blank or use `/`) |
| Build command | `npm run build` |
| Deploy command | `npx wrangler deploy` |
| Node.js version | `24` (`NODE_VERSION=24` if a build variable is needed) |

The root `package-lock.json` selects npm and pins Wrangler. Cloudflare's automatic
npm install runs the root `postinstall`, which installs both applications. If you
have disabled automatic dependency installation, use `npm ci && npm run build`
as the build command instead.

The deploy command runs after the build; it does not need to rebuild the apps.
The Worker name in `wrangler.jsonc` matches the existing `finance-repo` Worker.
Use Workers Builds, rather than a Pages-only static deployment, because NestJS
runs as Worker code.

## Deploy from your computer

Authenticate Wrangler for the account in `wrangler.jsonc`:

```sh
npx wrangler login
npm run deploy
```

`npm run deploy` builds both applications and then runs Wrangler. In CI, use a
scoped `CLOUDFLARE_API_TOKEN` secret instead of interactive login. Never commit a
token. The connected Cloudflare app and local Wrangler have separate credentials.

Deployment is an explicit action: installing, building, testing and the dry run
do not deploy or create remote resources.

## D1 database

The `DB` binding points to the separate `family-finance-test` D1 database created
during setup. Its account/database identifiers in `wrangler.jsonc` are resource
identifiers, not secrets. No existing family-finance database is reused.
Before intentionally targeting another database, update both its name and ID in
`wrangler.jsonc`. The infrastructure migration is already recorded in this test
database; household financial schemas are separate work.

Apply migrations to the local simulator:

```sh
npm run db:migrate:local
```

When a future migration is ready for that remote database, review it first and
run the explicit remote command:

```sh
npx wrangler d1 migrations apply DB --remote
```

Deploying code does not automatically apply database migrations. Local D1 data
is kept under the ignored root `.wrangler/` directory, separately from remote D1.

## Local development

Run the combined app in the local Workers runtime:

```sh
npm run db:migrate:local
npm run dev:cloudflare
```

Open http://localhost:8787. Restart this command after source changes to rebuild.
`/api/hello` returns `{ "message": "Hello World!" }`; `/api/health` queries the D1
binding and returns `{ "status": "ok", "database": "ok" }`.

For separate Node/Angular development, use two terminals after the root install:

```sh
npm --prefix backend run start:dev
npm --prefix frontend start
```

NestJS listens on port 3000 and Angular on port 4200. Angular's development proxy
forwards `/api/**` to port 3000. The D1 health route belongs to the Worker runtime.

## Checks

```sh
npm --prefix backend test
npm --prefix backend run test:e2e
npm --prefix backend run lint
npm --prefix frontend test -- --watch=false
npm run deploy:check
```

The current app includes the greeting integration and infrastructure health
check. Authentication and financial workflows remain future work.

Wrangler aliases the starter's missing optional NestJS packages to a module that
rejects their import, preserving Nest's optional-package handling. Before adding
class-validator/class-transformer, microservices or WebSockets, install the real
package and remove its corresponding alias from `wrangler.jsonc`.
